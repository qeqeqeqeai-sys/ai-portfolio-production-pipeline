# P2 Live Demo Runbook

## Purpose
Provide a reliable, presentation-safe execution sequence for live demonstrations, architecture walkthroughs, and reviewer sessions.

## Recommended 10-Minute Demo Flow
1. **00:00-01:30** — Platform positioning and boundary framing.
2. **01:30-03:30** — Architecture-first walkthrough using P1A/P1B assets.
3. **03:30-06:30** — Dashboard sequence through certified operational views.
4. **06:30-08:00** — Replay and certification evidence (D2/D3/D4).
5. **08:00-09:30** — Safety boundary reaffirmation and non-claims.
6. **09:30-10:00** — Closing statement and reviewer navigation guidance.

## Recommended 5-Minute Demo Flow
1. **00:00-00:45** — Platform identity and exclusions.
2. **00:45-01:45** — Architecture summary (bounded deterministic pipeline).
3. **01:45-03:30** — Dashboard highlights (deterministic visibility path).
4. **03:30-04:30** — Certification and playback references.
5. **04:30-05:00** — Close with governance-oriented framing.

## Startup Sequence
1. Confirm repository cleanliness (`git status --short`).
2. Start dashboard through certified operational method.
3. Verify key view rendering before screen-share begins.
4. Open relevant reports in separate tabs for rapid reference.
5. Keep fallback artifact deck ready.

## Architecture Opening
- Start with system identity: **Deterministic Institutional Expectation-Failure Intelligence Platform**.
- Explain bounded flow: data ingestion -> structural interpretation -> dashboard presentation -> certification traceability.
- Ground narrative in P1A institutional architecture and P1B visual package.
- State exclusions immediately to prevent misinterpretation.

## Dashboard Walkthrough Sequence
1. Show landing context and objective framing.
2. Show deterministic seeded-data visibility path (D1).
3. Show core structural interpretation panels from certified dashboard scope (O1–O10).
4. Highlight explainability and reviewer legibility over prediction claims.
5. Keep transitions scripted; avoid unscripted feature exploration.

## Replay and Certification Demonstration
- Reference D2 visibility certification for view-level confidence.
- Reference D3 supervisor playback for deterministic replay evidence.
- Reference D4 demo environment closeout for readiness confidence.
- Use reports folder navigation to show institutional documentation discipline.

## Safety Boundary Explanation
Use explicit, repeated language:
- no autonomous trading
- no target prices
- no portfolio optimization
- no trade execution
- no uncontrolled LLM reasoning
- no adaptive control systems
- no autonomous trading agents
- no predictive market forecasting
- no buy/sell/short recommendations

## Closing Statement
"This platform is designed as a deterministic, reviewable institutional intelligence layer for expectation-failure interpretation. It is intentionally bounded, explainable, and certification-backed for professional review settings."

## Fallback Plan if Dashboard Cannot Run Live
1. Move to architecture and certification artifacts first (P1A/P1B, D2/D3/D4).
2. Use prepared screenshots to preserve sequence fidelity.
3. Walk through deterministic seeded outputs via static evidence.
4. State runtime issue transparently without functional overstatement.
5. Offer follow-up live session after environment remediation.

## Final Supervisor Notes
- Prioritize credibility over breadth.
- Keep language measured, technical, and governance-oriented.
- Never imply forecasting, optimization, or autonomous execution capability.
- Maintain architecture-first sequencing in all interview contexts.
