# D8.B2-R GitHub Actions Supabase Diagnostics Guide

## Purpose
This guide describes how to manually run the **D8.B2-R Real Supabase Diagnostics (Read-Only)** GitHub Actions workflow.

The workflow performs **read-only diagnostics only** and does **not** execute write/backfill actions.

## Required GitHub Secrets
Add the following repository-level secrets:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

### How to add repository secrets
1. Open the GitHub repository.
2. Go to **Settings → Secrets and variables → Actions**.
3. Select **New repository secret**.
4. Add `SUPABASE_URL` with your Supabase project URL.
5. Add `SUPABASE_SERVICE_ROLE_KEY` with your service role key.

> ⚠️ **Security warning:** Never expose `SUPABASE_SERVICE_ROLE_KEY` in logs, screenshots, commits, docs, chat, or tickets. Treat it as highly sensitive production credential material.

## Manual Workflow Execution
1. Open the repository **Actions** tab.
2. Select workflow: **D8.B2-R Real Supabase Diagnostics (Read-Only)**.
3. Click **Run workflow**.
4. Choose branch and confirm run.

The workflow command executed is:

```bash
PYTHONPATH=. python scripts/run_d8_b2r_real_supabase_diagnostics.py
```

## Generated Report and Artifact
- Local report path generated by the workflow run:
  - `reports/d8_b2r_real_supabase_diagnostics_status_report.md`
- Uploaded artifact name:
  - `d8-b2r-real-supabase-diagnostics-report`

## Expected `SOURCE_*` Statuses
During and after the run, validate these source-diagnostic outcomes in the generated report:

- `final_status` should indicate source diagnostic outcome (expected healthy state: `SOURCE_OK`).
- `dry_run_source_status` should indicate dry-run source-check outcome (expected healthy state: `SOURCE_OK`).

If either value is not `SOURCE_OK`, investigate replay/manifest source consistency before any downstream operational execution.

## Read-Only Confirmation
The generated report must include explicit read-only confirmations:

- `Mode: READ-ONLY diagnostics`
- `Explicit no-write confirmation: true`

These markers confirm no write/backfill execution was performed by this diagnostics workflow.
